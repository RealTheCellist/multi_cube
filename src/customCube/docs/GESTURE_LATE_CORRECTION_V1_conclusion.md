# Gesture 방향 오인식 — Late Correction 추가 결과 보고

## 무엇을 했나

이전 STEP3 실측에서 Right face(면 경계 뚜렷한 지점)는 마진 스케일링
게이트로 완전히 해결됐지만, Top face 같은 진짜 동률에 가까운 지점(마진
0.042)은 여전히 개선 폭이 작다는(50.0%/43.3%) 한계가 남아있었다. 사용자가
"좀더 개선해보자"고 요청해 다섯 번째 방향인 **잠근 후에도 한 번 더
정정할 수 있는 게이트(Late Correction)**를 설계·검증·반영했다.

기존 게이트는 축이 한 번 잠기면 다시 보지 않는다. 새 로직은 잠긴 뒤에도
같은 방향 벡터로 두 후보를 계속 비교하다가, 반대 후보가 확신 있게
(마진 ≥ 기존 `LOW_CONFIDENCE_MARGIN`) 앞서면 **한 번만** 축을 바꾼다 —
이미 커밋된 무브가 없는 라이브 스크럽 단계이므로, 잘못 시작한 회전을
되돌리고(`endTurn(null)`) 올바른 축으로 다시 시작(`beginTurn()`)한다.
잘 분리된 면은 마진이 항상 임계값보다 훨씬 커서 이 로직이 발동 자체를
하지 않으므로, 기존에 잘 동작하던 케이스를 건드릴 수 없는 구조다.

## 실제 수치

헤드리스 시뮬레이션으로 임계값(0.10~0.35)을 스윕해 0.15(기존
`LOW_CONFIDENCE_MARGIN`과 동일값 재사용)를 채택한 뒤, 실제 브라우저에서
프로덕션 코드 그대로 N=60/방향 재검증했다(임시 프로브 사용 후 전부 되돌림,
`git diff` 0줄 확인):

| 지점 | 이전(V4, 교정 없음) | 이번(late correction 포함) |
|---|---|---|
| Right face(마진 0.044) | 0.0% / 0.0% | 0.0% / 0.0% — 불변 |
| Top face(마진 0.042) | 50.0% / 43.3% | **41.7% / 33.3%** — 8.3~10.0%p 개선 |
| Front face(회귀 검사) | 3.3% / 3.3% | **0.0% / 0.0%** — 오히려 개선 |

교정 발동 비율은 Top face 28.3~36.7%(저마진 지점에서 자주), Front face
3.3%(거의 발동 안 함), Right face 0% — 설계 의도대로 동작했다.

## 판정

| 기준 | 결과 |
|---|---|
| Front face 회귀 없음 | **통과** — 오히려 개선 |
| Right face 유지 | **통과** — 완전히 불변 |
| Top face 추가 개선 | **통과** — 실측 8.3~10.0%p 개선 |
| 완전 해결(100%) | **미달성** — 마진이 0에 가까운 진짜 동률은 순수 각도 비교의 이론적 한계 |

## 결론

지금까지 시도한 5가지 방향 중 실측 기준 가장 뚜렷한 개선이라 이미
프로덕션에 반영했다(`customSwipeControls.ts`, +69/-2줄). Right face류
(면과 면이 뚜렷이 갈리는 지점)의 오인식은 확실히 해결됐고, Top face류
(거의 동률인 지점)도 유의미하게 개선됐지만 완전히 사라지지는 않았다 —
이는 두 후보의 화면상 방향이 실제로 거의 평행해지는 순수 기하학적 한계로,
게이트 튜닝만으로는 이 이상 넘기 어렵다.

**다음 단계 제안**: 남은 Top face류 오인식을 더 줄이려면 카메라 각도
자체를 조정하는 접근(이전에 시도했다가 다른 면을 악화시켜 기각한 Yaw
조정과는 다른 조합)이나, 터치 압력·속도 등 각도 외의 신호를 추가하는
방향이 필요해 보인다. 다만 이 정도 개선만으로도 실사용 체감에는 충분할
가능성이 있으니, 사용자가 직접 체감을 확인해보고 추가 투자 여부를
판단하는 것을 권한다. 모델 연구는 여전히 보류 상태로 유지한다 — 이번
개선도 순수 무브먼트 시스템 쪽 수정이었다.
