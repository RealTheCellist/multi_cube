# Gesture Top Face 추가 개선 — CORRECTION_MARGIN 0.07 결과 보고

## 무엇을 했나

"Top face가 문제구나... 개선할 방법 없나?"는 질문에 두 가지 방향을
검토했다 — 카메라 각도 변경은 이미 예전 Sprint(`CAMERA_ANGLE_EXPANSION_V1`)
에서 Right face와의 근본적 트레이드오프로 기각된 이력이 있었고, 대기
구간에 실시간 시각적 힌트를 주는 방향은 검증 방식(합성 스와이프
시뮬레이션)으로 효과를 측정할 수 없어 사용자가 거부했다. 남은 저위험
레버는 방금 넣은 Late Correction의 판정 임계값(`CORRECTION_MARGIN`)을
더 낮추는 것이었고, 사용자가 0.07을 직접 지정해 적용·검증했다.

## 실제 수치

헤드리스 시뮬레이션(N=500/방향)으로 먼저 확인한 뒤, 실제 브라우저에서
프로덕션 코드 그대로 N=60/방향 재검증했다(임시 프로브 사용 후 전부
되돌림, `git diff` 0줄 확인):

| 지점 | 0.15(이전 반영분) | 0.07(이번) |
|---|---|---|
| Right face(마진 0.044) | 0.0% / 0.0% | 0.0% / 0.0% — 불변 |
| Top face(마진 0.042) | 41.7% / 33.3% | **35.0% / 35.0%** — 평균적으로 추가 개선 |
| Front face(회귀 검사) | 0.0% / 0.0% | 0.0% / 0.0% — 불변 |

Top face의 교정 발동 비율은 28.3~36.7%에서 51.7~55.0%로 크게
늘었다 — 축이 스와이프 도중 한 번 바뀌는 빈도가 절반을 넘는다는 뜻이며,
"정확도를 더 짜내는 대신 mid-gesture flip이 늘어난다"는 사전 시뮬레이션의
트레이드오프 예측과 정확히 일치했다.

## 결론

지금까지 시도한 6가지 방향(V3 게이트 → 카메라 각도 → 다중 샘플 평균 →
V4 마진 스케일링 게이트 → Late Correction → 이번 임계값 강화) 중 Top
face 지점의 실측 오인식률을 가장 많이 끌어내렸다. 다만 두 가지를
솔직하게 밝힌다:

1. **완전히 해결되지는 않았다** — 여전히 1/3 이상의 확률로 오인식되는
   진짜 동전 던지기에 가까운 지점이며, 이는 두 후보 축의 화면상 방향이
   실제로 거의 평행해지는 순수 기하학적 한계다.
2. **트레이드오프가 커졌다** — 축이 도중에 바뀌는 빈도가 절반을 넘어,
   사용자가 스와이프 중 "레이어가 갑자기 바뀌는" 느낌을 더 자주 받을 수
   있다. 정확도와 체감 안정성 사이의 트레이드오프이며, 이번 값(0.07)은
   사용자가 정확도 쪽을 더 우선한 선택이다.

이 이상 추가 개선을 원한다면 순수 알고리즘 튜닝만으로는 한계가
뚜렷하다 — 카메라 각도(이미 기각), 다른 신호(터치 압력/속도, 대부분
기기에서 신뢰도 낮음), 또는 UX적 완화(이미 있는 Undo 버튼 강조) 중
하나를 골라야 한다.
