========================================
Contract Dependency Report -- Solver Contract Analysis Sprint v1
========================================

1. 계약의 정확한 위치 (읽기 전용 확인, fiveByFiveEdges.ts 미수정)
----------------------------------------------
"즉시 WrongWing 순 개선이 있어야만 성공으로 인정한다"는 계약은 정확히
tryFixWing()의 마지막 검증 한 줄에 있다:

  const clone = cloneCubies(cubies);
  applySeq(clone, fullSeq);
  if (wrongWingCount5(clone) < before) return fullSeq;

즉 tryFixWing()은 구조적으로 유효한(BFS가 찾아낸) 이동이라도 이 조건을
통과하지 못하면 그 이동 자체를 버리고 다음 후보로 넘어간다. 이 문서의
근거가 된 First-Hop Failure Analysis Sprint v1이 발견한 것처럼,
enumerateWingCandidates()(같은 검색이지만 이 마지막 줄이 없는 버전)는
구조적으로 유효한 이동을 여러 개 찾아내는 경우가 많다(PAIR_CONFLICT
37건 평균 candidate 수 ~5개) -- tryFixWing()은 그중 이 조건을 만족하는
것만 받아들인다.

2. 계약이 적용되는 다른 위치들 (읽기 전용 확인)
----------------------------------------------
tryFlipWingsInPlace() / tryExactCaseMatch() / bestFixOverall() /
tryEndgameMultiPly() -- 전부 비슷하게 "이 함수가 반환하는 fix는 적용하면
개선된다"는 것을 스스로 검증한 뒤에만 반환한다 (각 함수 자체의 기존 주석
확인, 로직 미수정). fiveByFiveEdgeExecutor.ts의 runPrimaryPipeline()은
이 함수들의 반환값이 "moves.length > 0"이면 그대로 적용하는 소비자일
뿐이며, 자체적으로 추가 검증을 하지 않는다 -- 즉 계약은 Executor가 아니라
전부 fiveByFiveEdges.ts 내부 함수들 자신에게 있다.

3. 예외: Recovery는 이미 "일시적 후퇴"를 허용한다 (중요한 선례)
----------------------------------------------
fiveByFiveEdgeRecovery.ts의 attemptRecovery()를 읽어보면(수정 없음, 읽기
전용), 이 아키텍처 안에 이미 "즉시 개선 없이 일시적으로 후퇴했다가 나중에
개선"을 시도하는 유일한 경로가 존재한다:

  const before = wrongWingCount5(scratch);
  applySeq(scratch, best.moves);  // DISRUPT -- 의도적으로 wrongWing을 늘릴 수 있음
  const afterDisrupt = wrongWingCount5(scratch);
  ...
  const retryMoves = retryTask(scratch, retryDeadline);
  if (retryMoves.length > 0) {
    const finalWrong = wrongWingCount5(scratch);
    if (finalWrong < originalBaseline) { ...성공... }
    // 순 개선 아직 없음 -- 계속 진행 (다음 라운드가 이 중간 상태에서 시작)
  }

즉 Recovery는 "즉시 개선"이 아니라 "여러 라운드에 걸친 최종 개선"을
검증 기준으로 삼는다 -- 정확히 이번 Sprint가 묻는 질문의 넓은 버전을
이미 실제로 시도했다는 뜻이다. 그런데 Adaptive Executor v2가 이미
측정한 바로는, 이 메커니즘이 실제로 포착된 정체 상태(stuck residual)에
적용됐을 때 30배 예산(500ms)을 줘도 20건 중 0건 성공했다.

이것이 이번 Sprint의 핵심 배경이다: "일시적 후퇴 허용"이라는 아이디어
자체는 새롭지 않고 이미 넓은 형태로 시도되어 실패했다. 이번 Sprint가
다른 점은 Recovery의 광범위한 교란 탐색이 아니라, CycleChase가 이미
탐지해낸 바로 그 WANTS-Cycle을 따라 좁게, 구조적으로 제한된 형태로만
"일시적 후퇴"를 시도한다는 것이다 -- Recovery의 실패가 이번 결과를
미리 결정하지는 않지만, 회의적으로 봐야 할 강력한 선례임을 숨기지 않고
명시한다.

종합
----------------------------------------------
계약은 fiveByFiveEdges.ts의 각 tryXxx() 함수 자체에 있으며, Planner나
Executor가 별도로 강제하는 것이 아니다. Recovery는 이미 "여러 라운드
후 개선"을 시도하는 유일한 예외적 경로이지만 실제 정체 상태에서는
0/20으로 실패했다 -- 이 Sprint는 그 아이디어를 CycleChase가 찾아낸
Cycle 구조 안으로 좁혀서 다시 검증한다.
